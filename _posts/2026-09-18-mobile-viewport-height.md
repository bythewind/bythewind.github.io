## 现象

桌面浏览器里，首屏内容和底部按钮都完整显示。到了手机浏览器，地址栏和底部工具栏占据部分空间，首屏最后一个按钮被推到可视区域之外。

页面本身没有横向溢出，开发者工具里元素高度也确实等于视口高度。问题看起来像是“最后一个元素掉了下去”。

## 先确认高度基准

移动浏览器至少有几种不同含义的“视口高度”：

| 概念 | 大致含义 | 常见用途 |
| --- | --- | --- |
| `vh` | 初始视口高度 | 兼容旧浏览器或不严格要求精确的场景 |
| `svh` | 浏览器工具栏展开时的最小可视高度 | 希望首屏始终完整可见 |
| `dvh` | 随工具栏变化而变化的动态可视高度 | 全屏应用、游戏或需要实时跟随的画布 |

`100vh` 在很多移动浏览器中按较大的初始视口计算。工具栏出现后，CSS 元素仍然保持原来的高度，于是底部内容落到了屏幕外。

## 修复方式

如果目标是让整段首屏在工具栏展开时也能完整看到，优先使用 `svh`，同时保留 `vh` 作为旧浏览器的回退：

```css
.hero {
  min-height: 100vh;
  min-height: 100svh;
}
```

如果界面需要随浏览器工具栏变化实时伸缩，例如全屏编辑器，可以考虑 `dvh`：

```css
.workspace {
  height: 100vh;
  height: 100dvh;
}
```

不要为了消除一个被遮挡的按钮，不加区分地把所有 `100vh` 都替换成 `dvh`。动态单位会在滚动时改变尺寸，可能让固定布局或动画产生抖动。

## 验证

在真实手机或移动端模拟器中依次检查：

1. 地址栏展开时，首屏关键操作是否可见；
2. 向下滚动、工具栏收起后，页面是否出现异常跳动；
3. 横屏时是否仍保留合理的内容高度；
4. 不支持新单位的浏览器是否仍能通过回退值正常显示。

这次问题最终不是“少写了一个 `overflow: hidden`”，而是高度基准选错了。先确认元素的实际可视区域，再选择对应单位，通常会比继续调整间距更可靠。
